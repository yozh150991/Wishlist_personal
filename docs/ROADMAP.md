## Етап 2 — Автентифікація і каркас ✅
- [x] Vite + React 18 + TypeScript (strict), збірка перевірена
- [x] Дизайн-токени у власному CSS, темна/світла/системна тема без спалаху при завантаженні (ADR-015)
- [x] i18n uk / pl / en, ключі звірені між словниками, запасна мова — українська
- [x] Реєстрація, вхід, скидання і зміна пароля; помилки Supabase перекладено за кодами
- [x] `<RequireAuth>` зі скелетоном замість редіректу під час завантаження сесії (ADR-016)
- [x] Каркас застосунку, порожній `/lists`, сторінка налаштувань
- [x] Playwright: шість сценаріїв навігації та захисту роутів
- [ ] Форми обгорнути в `<form>` — зараз Enter обробляється вручну, це гірше для менеджерів паролів
- [ ] Українські й польські шаблони листів у Supabase
- [ ] Свій SMTP замість вбудованого (вбудований шле ~3 листи/год)

## Етап 3 — Списки й позиції ✅
- [x] CRUD списків: назва, опис, валюта, дата події
- [x] CRUD позицій; обовʼязкова лише назва, посилання й ціна можуть бути порожні
- [x] Сітка карток; пріоритет показано смужкою збоку, куплене й подароване приглушено

- [x] Розмір партії 10/25/50/100, сортування за датою, назвою, ціною, пріоритетом у два напрямки
- [x] Пошук по назві з відкладанням 300 мс, фільтр по статусу й діапазону ціни
- [x] Підсумки: сума активних, кількість без ціни, кількість подарованого
- [x] Перемикання статусу `active → purchased → gifted` однією кнопкою
- [x] Виправлено сортування і пагінацію в `list_items_page` (ADR-017)
- [ ] pgTAP-тести інваріантів — борг з етапу 1
- [ ] Масові дії над позиціями (вибір кількох) — прийдуть разом із шерингом на етапі 5

## Етап 4 — Парсер посилань ✅
- [x] FastAPI-сервіс, Docker з read-only і без root
- [x] JSON-LD → microdata → OpenGraph → Twitter → `<title>`, джерело кожного поля в `confidence`
- [x] Розбір цін у польському, англійському й українському записі; валюта зі знака або коду
- [x] SSRF-фільтр з перевіркою всіх адрес DNS і кожного редіректа; ліміт 2 МБ потоком, таймаут 8 с
- [x] Обмеження частоти на користувача, кеш відповідей на 15 хв
- [x] Перевірка токена через Supabase, без секретів у сервісі (ADR-018)
- [x] Кнопка «Заповнити» у формі позиції; уже введене вручну не перезаписується
- [x] 27 тестів pytest, зокрема вісім на SSRF
- [ ] Деплой на GCP VM за nginx з TLS
- [ ] Парсери під конкретні магазини — за потреби, поки не замовлено
- [ ] Allegro не піддається універсальному парсингу через антибот-захист. Варіанти, якщо це стане важливо: офіційне API Allegro (реєстрація застосунку + OAuth) або розширення для браузера, яке читає вже відкриту сторінку

## Етап 5 — Шеринг і бронювання
- Режим вибору позицій, діалог «Поділитися»
- Сторінка `/s/:token` для гостя (адаптивна, без реєстрації)
- Анонімне бронювання, `guest_key` у localStorage
- Сторінка «Мої посилання»: відкликання, перегляди, термін дії
- Банер для власника у власному посиланні
- Playwright: повний цикл шеру в окремому browser context

## Етап 6 — PWA, підсумки, експорт
- Service Worker, IndexedDB, черга офлайн-змін
- Статуси `purchased` / `gifted`, режим «підбити підсумки» після події
- Експорт CSV і JSON, імпорт із валідацією і попереднім переглядом
- Іконки, маніфест, встановлення на телефон
- Lighthouse ≥ 90 за всіма категоріями
