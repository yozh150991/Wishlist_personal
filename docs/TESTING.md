# Стратегія тестування

## Рівні

| Рівень | Інструмент | Що покриває | Стан |
|---|---|---|---|
| БД / RLS | pgTAP (SQL) | політики доступу, інваріанти приватності | **не написано — борг з етапу 1** |
| Парсер | pytest | витяг даних, SSRF-захист, перевірка токена | є |
| Фронтенд, чиста логіка | Playwright без браузера | функції без DOM (`safeNext`) | є |
| E2E | Playwright + TypeScript | сценарії користувача і гостя | є частково |

Інваріанти приватності зараз перевірено лише вручну — SQL-блоками з `SETUP.md`, розділ 6, і сценаріями Playwright на шеринг. Автоматичної перевірки на рівні бази, яка стерегла б кожну нову міграцію, поки немає.

## Тести RLS — найважливіші

Мають іти першими, бо перевіряють суть продукту. Мінімальний набір:

1. Користувач A не читає списки користувача B (`select` повертає 0 рядків, не помилку).
2. Користувач A не додає позицію в список B.
3. Anon не читає `items`, `lists`, `shares` напряму — жодним запитом.
4. **Власник не читає `reservations`** — ні `select`, ні через JOIN, ні через будь-яку RPC.
5. `get_shared_list` з відкликаним токеном кидає `revoked`.
6. `get_shared_list` з простроченим токеном кидає `expired`.
7. `get_shared_list` не повертає позиції зі статусом `purchased`/`gifted`.
8. При `hide_prices: true` поле `price` дорівнює `null` у відповіді.
9. `create_share` ігнорує id позицій з чужого списку.
10. Власник, автентифікований, отримує `reserved_qty: null` (ADR-009).
11. Жодна функція в схемі `public` не має `EXECUTE` для `PUBLIC`, крім явно дозволених гостьових (CLAUDE.md §3.4).

### Акаунт для E2E

`items.spec.ts` і `sharing.spec.ts` входять під справжнім акаунтом і без `E2E_EMAIL` та `E2E_PASSWORD` пропускаються:

```powershell
$env:E2E_EMAIL = "..."; $env:E2E_PASSWORD = "..."
npx playwright test
```

Окремої тестової бази немає: тести пишуть у ту саму бойову Supabase, що й застосунок. Тому для E2E потрібен **окремий акаунт**, не особистий — сценарії створюють списки з назвами `E2E <час>`, і вони залишаються в базі.

Без `E2E_BASE_URL` тести йдуть проти `localhost:5173` і самі запускають `npm run dev`. Проти бойового фронтенду:

```powershell
$env:E2E_BASE_URL = "https://wishlist-personal.vercel.app"
```

## Тести парсера (pytest)

**SSRF** — `test_ssrf.py`
- `127.0.0.1`, `localhost`, `169.254.169.254`, `10/8`, `192.168/16`, `172.16/12`, `[::1]`, `0.0.0.0` → `BlockedHost`.
- Схеми `file`, `ftp`, `gopher` → `BlockedHost`.
- Хост, що не резолвиться → `BlockedHost`.
- Публічний хост дозволено. Єдиний тест, якому потрібна мережа.

**Токен** — `test_auth.py`, мережу заблоковано заглушкою
- Немає заголовка, порожня схема, `Basic` → `401 missing_token`.
- Кирилиця, не-ASCII байти, не три частини, зайві символи, понад 8 КБ → `401 invalid_token`, і звернення до Supabase не відбувається (ADR-023).
- Токен правильної форми доходить до Supabase.

**Витяг даних** — `test_extract.py`
- Фікстури HTML на кожен шлях витягу: JSON-LD, microdata, OpenGraph, «нічого» (`partial: true`, назва з `<title>`).
- Розбір цін у польському, англійському й українському записі, зокрема `9,99/szt.` і `299 zł.`.
- Евристика ціни: працює без розмітки, поступається розмітці, не бере «365» з «IKEA 365+» (ADR-019).
- Рекламні параметри відкидаються, змістовні лишаються (ADR-020).
- `supabase_ready` розпізнає незаповнений шаблон.

⬜ Не покрито: редирект із публічного домену на приватну IP і обрізання сторінки понад `PARSER_MAX_BYTES` — обидва шляхи потребують підміни HTTP-відповідей. Сторінка понад ліміт **не** дає `413`: вона обрізається, бо мета-теги лежать у `<head>`.

```powershell

cd services\parser
pip install -r requirements-dev.txt
pytest

cd app
npm run typecheck
npx playwright test
```
