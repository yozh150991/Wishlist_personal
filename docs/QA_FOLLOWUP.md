## Продукт і пріоритети

Продукт — приватні списки бажань з вибірковим поширенням, анонімними бронями та спільними подарунками. Основні ролі: власник, інший авторизований користувач, гість без ключа, гість із ключем, організатор збору, учасник збору. Ключові ризики: розкриття сюрпризу власнику, доступ до чужих даних, втрата офлайн-змін, спотворення ціни та неможливість відновити бронь.

Автоматизація охоплює всі основні модулі за наведеною картою. Це **не твердження про 100% шляхів, коду або комбінацій**. Кожна зелена перевірка підтверджує лише свої умови й оракул. Покриття реального доставлення листів/push, OAuth провайдера та встановленого PWA не підміняємо тестами із заглушками.

### BUG-QA-23 — ціна JSON втрачає десяткову крапку

**Де:** `transfer.ts`, `parseJsonFile → rowToItem → parsePrice`.
**Кроки:** імпортувати `{"items":[{"title":"Lamp","price":1.234}]}`.
**Очікувано:** 1.23 згідно з округленням імпорту до копійок (або явне попередження про надлишкову точність), ніколи 1234.
**Факт:** 1234 без попередження; 12.345 → 12345, 0.125 → очищена ціна.
**Причина:** JSON number перетворюється на рядок і проходить правила локалізованого групування розрядів.
**Рекомендація:** зберігати тип JSON-числа до валідації та округлення; локалізоване групування застосовувати лише до тексту. Не змінювати задуманий CSV `1.234` = 1234.
**Виправлено (ADR-071):** ціна, що у JSON має тип `number`, іде повз правила тексту й округлюється за десятковим записом, половина вгору (`roundToCents` у `transfer.ts`); текст і CSV — як раніше.

### BUG-QA-24 — формат дати прийнято за календарну валідність

**Де:** `transfer.ts`, `checkList`.
**Кроки:** імпортувати `{"list":{"event_date":"2026-02-29"},"items":[{"title":"Lamp"}]}`.
**Очікувано:** попередження `transfer.issues.eventDate`, очищена дата, решта списку придатна.
**Факт:** дата прийнята без попереджень. Те саме для 1900-02-29, 31 квітня, місяців 00/13 і дня 00. Форма створення вже відкидає такі дати.
**Наслідок:** підготовлений імпорт містить значення, непридатне для колонки PostgreSQL `date`; UI-прохід із живою БД у цьому тесті не використано.
**Рекомендація:** перевіряти календарну дату, а не лише regex форми ISO.
**Виправлено (ADR-071):** `checkList` перевіряє дату тими самими правилами, що й форма (`dateTextToIso`).

### BUG-QA-25 — обрізання Unicode

**Де:** `transfer.ts`, обрізання `note` і `section` через `slice`.
**Кроки:** імпортувати нотатку з 999 символів `a` і `🎁tail`; для розділу — 59 `a` і той самий хвіст.
**Очікувано:** валідний Unicode після обрізання, без половини emoji.
**Факт:** останній символ — самотній high surrogate `\uD83C`. PostgreSQL не може зберегти його як валідний UTF-8; тут підтверджено пошкодження результату парсингу, не фактичну відмову мережевого імпорту.
**Рекомендація:** обрізання за code points із узгодженими обмеженнями БД; перевірити також назву списку, опис і ознаки.
**Виправлено (ADR-071):** довжини й обрізання в імпорті — у code points (`charLength`, `clip`) для назви позиції, нотатки, розділу, назви й опису списку та ознак.

### BUG-QA-26 — аварія перетворення об'єкта в рядок

**Кроки:** `parseJsonFile('{"items":[{"title":{"toString":null}}]}', 'QA')`.
**Очікувано:** результат із помилкою типу/рядка, без винятку.
**Факт:** `TypeError: Cannot convert object to primitive value` у `trimmed`.
**Вплив:** UI має зовнішній catch, тому це не доказ падіння всього застосунку; файл переривається з технічною помилкою замість пояснення поля.
**Рекомендація:** явний whitelist примітивних типів, об'єкти полів не коерсити через `String`.
**Виправлено (ADR-071):** `trimmed` приводить до тексту лише рядок, число й boolean; решта — порожнє поле.

### BUG-QA-27 — JSON-LD неправильних типів

**Кроки:** магазин повертає `<script type="application/ld+json">{"@type":7}</script><title>Fallback lamp</title>`; викликати `/parse`. Другий клас: `{"@type":"Product","name":{"text":"Lamp"}}`.
**Очікувано:** ігнорувати неправильні поля, повернути 200 з резервною назвою й `partial:true`.
**Факт:** HTTP 500. `@type` число/boolean не підтримує `in`, `name` об'єкт/масив/число потрапляє в `re.sub`.
**Рекомендація:** перевіряти типи до використання і дозволяти fallback окремого поля. HTTP-тест використовує справжні FastAPI й extract; завантаження сторінки та auth замінені фікстурами.
**Виправлено (ADR-071):** `_types` і `_text` у `extract.py`; валюта приймається лише рядком.

### BUG-QA-28 — велике JSON-число

**Кроки:** Product із `offers.price`, що містить ціле з 309 або 400 дев'яток, на `/parse`.
**Очікувано:** 200, `price:null`, `partial:true`.
**Факт:** 500: `math.isfinite(raw)` на Python int кидає OverflowError ще до захисної перевірки float.
**Рекомендація:** обмежувати розмір/діапазон перед конвертацією або обробляти OverflowError.
**Виправлено (ADR-071):** ціле порівнюється з межею `numeric(12,2)` до `float()`; межа діє для всіх цін парсера.

### BUG-QA-29 — мінус стає плюсом

**Кроки:** `parse_price('-49,90 zł')`, `parse_price('-0.01')`.
**Очікувано:** None — від'ємна ціна невалідна, як уже реалізовано для числового -5.
**Факт:** 49.9 та 0.01: regex починає захоплення з цифри й губить знак.
**Рекомендація:** розпізнавати й відкидати від'ємні цінові токени до очищення рядка.
**Виправлено (ADR-071):** мінус (`-`, U+2212) перед числом, не після літери чи цифри, робить ціну недійсною.

### BUG-QA-30 — неправдиве підтвердження офлайн-збереження

**Де:** `outbox.ts`: `run` → `enqueue`; `idb.ts`: `openDb`.
**Умови:** REST недоступний, `indexedDB.open` кидає SecurityError (наприклад, сховище заборонене).
**Кроки тесту:** заблокувати REST через Playwright route; підмінити лише `IDBFactory.prototype.open`; викликати справжній `outbox.run` для delete; прочитати лічильник черги. Підміна відновлюється в finally.
**Очікувано:** відмова, яку UI може показати; не `queued` без збереженого запису.
**Факт (код і локальний запуск модуля):** `openDb` повертає null; `enqueue` мовчки завершується; `run` повертає `queued`, pending = 0. Після reload локальну зміну немає звідки повторити.
**Рекомендація:** enqueue мусить підтверджувати commit IndexedDB; невдале відкриття/транзакція має відхиляти операцію. Перевірити й false від `txDone`, який зараз ігнорується.
**Виправлено (ADR-071):** `enqueue` повертає `true` лише після commit; інакше `run` кидає ту саму мережеву помилку, і екран показує «немає з'єднання». Підтверджено в Chromium (desktop і mobile).

## Гість на iPhone поза Safari і в месенджерах

Прогін 8.2 на iPhone охопив Safari і PWA. Гості ж часто відкривають посилання на список у Chrome або просто з месенджера — у його вбудованому браузері, де нові вкладки поводяться по-своєму. «Забронювати й перейти» (ADR-075) розраховане на те, що вкладка може не відкритися, — тут це перевіряємо на живих застосунках. Знайдене — як BUG-QA-31 і далі.

- [x] Chrome на iPhone: «Забронювати й перейти» — вкладка «Бронюємо…» йде в магазин після броні, або після броні є «Перейти в магазин»; магазин без броні не відкривається — пройдено 20 листопада
- [x] Telegram (iPhone й Android): відкрити посилання на список із чату → «Забронювати й перейти» — те саме; код броні видно й копіюється — пройдено 20 листопада
- [x] Instagram або Facebook Messenger (iPhone й Android): те саме — пройдено 20 листопада
- [x] У вбудованому браузері месенджера → «Відкрити в браузері» → бронь видно через «Уже маю броні» й код — пройдено 20 листопада
- [x] Картка посилання в месенджері (ADR-060): назва списку й дата — пройдено 20 листопада
- [x] Картка для бота не дістається людині (кеш картки, доповнення до ADR-060) — на production, у PowerShell, після деплою з цим виправленням. Токен — зі свого тестового посилання; `Read-Host` не лишає його в історії команд, у нотатки його не писати: — пройдено 20 листопада

  ```powershell
  $t = Read-Host "token"
  $u = "https://wishlist-personal.vercel.app/l/$t"
  $bot = "TelegramBot (like TwitterBot)"
  $ua = "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/130.0.0.0 Safari/537.36"
  $show = '^HTTP|^cache-control|^vary|^x-vercel-cache|og:title|id="root"'
  # Бот, і тим самим рядком одразу за ним — браузер. Повторити тричі поспіль.
  curl.exe -s -i -A $bot $u | Select-String $show; "-----"; curl.exe -s -i -A $ua $u | Select-String $show
  # Мертве посилання й людина просто на адресі функції.
  curl.exe -s -i -A $bot "https://wishlist-personal.vercel.app/l/nope" | Select-String $show
  curl.exe -s -i -A $ua "https://wishlist-personal.vercel.app/api/card?p=l&t=$t" | Select-String $show
  ```

  Має бути. **Бот** (до риски): `200`, `cache-control: private, no-store`, `vary` з `User-Agent`, `x-vercel-cache` — не `HIT` і не `STALE` (звично `MISS`), рядок з `og:title` — назвою посилання (кирилиця в консолі може бути нечитабельна — це консоль), рядка `id="root"` немає. **Браузер** (після риски): рядок `<div id="root">`, рядка `og:title` немає, `cache-control` — не `private, no-store` (це статичний `index.html`; `x-vercel-cache: HIT` тут нормальний). В усіх трьох повторах однаково — це й є перевірка: браузер жодного разу не отримав картку. **`/l/nope`**: ті самі заголовки, що в бота, `og:title` — «Wishlist». **`/api/card` з браузерним user-agent**: картка, і теж `private, no-store`. Якщо браузер бодай раз отримав `og:title` або бот — `x-vercel-cache: HIT`, це дефект: записати як BUG-QA з виводом команд без токена.

Готово, коли жоден гість не відкрив магазин без броні й кожна бронь повертається кодом.

## «Як минуло свято?» на головній (ROADMAP 8.13)

Картка, яка була лише на сторінці списку, тепер є й на «Моїх списках» — одна на всі минулі свята з нерозібраним. Автотест (`after-event-v2.spec.ts`) проходить шлях з акаунтом на локальній базі; тут — живий акаунт, телефон і три мови. Дату свята найпростіше ставити в «Налаштуваннях списку»: вчора — і картка вже є.

- [ ] Список із двома актуальними позиціями й датою «сьогодні» — на головній картки для нього немає; дата «вчора» — є: «Свято минуло · …», назва списку посиланням і «2 позиції не розібрані»; жодного слова про гостей, броні чи «хтось узяв»
- [ ] Два-три таких списки з різними датами — одна картка з пігулками, найсвіжіше свято вибране першим; інша пігулка міняє назву й кроки; довга назва в пігулці обрізається трьома крапками й не розпирає екран телефона
- [ ] «Перенести, що ще хочу» на головній → відкривається сторінка списку з уже відкритим вікном «Що ще хочеш?», усе вибрано; «Скасувати» → F5 — вікно саме не відкривається
- [ ] «Позначити отримане» на головній → вікно «Що подарували?», нічого не вибрано наперед; позначити одне → на головній «1 позиція не розібрана»
- [ ] «Повторити на …» на головній → вікно повтору з роком у назві, посунутим на рік; «Створити» відкриває новий список із неподарованим
- [ ] «Пізніше» на головній → свято зникає з картки (інше стає на його місце або картки немає); на сторінці цього списку картки теж немає. - [ ] Щорічний список, свято якого було ~11 місяців тому (до річниці менше місяця), не в архіві, з нерозібраним — на головній лише нагадування «Повторити … на …», без картки «Як минуло свято?» для нього; «Не цього разу» — картка для нього не зʼявляється

### BUG-QA-35 — «Уже куплено» не відмінити на місці; у «Моїх бронях» перша кнопка виглядає виділеною

**Де:** гостьова сторінка `/l/…` на iPhone, версія 0.2.18.
**Факт:** 1) гість випадково натиснув «Уже куплено», і повернути «Ви берете» можна було лише через «Мої броні» → «Ще не куплено» — туди ніщо не вело; 2) у «Моїх бронях» навколо першої «Уже куплено» — рамка, наче це рекомендована дія.
**Причина:** 1) «Ще не куплено» навмисне не стоїть на картці (від випадкового дотику), але й дороги до неї не було; 2) рамка — фокус, який `showModal()` ставить на перший елемент; виправлення BUG-QA-32 прибирало його лише з полів.
**Зроблено (0.2.19):** після «Уже куплено» шість секунд висить «Відмінити»; позначка йде на сервер одразу, а «Відмінити» відправляє зворотну — не як у «Зняти», бо відкладена позначка губилась би з закритою вкладкою; на купленій картці — «Не купили? Змінити в „Моїх бронях“»; на сенсорному екрані `SheetV2` переносить на вікно будь-який перший фокус. E2E — `guest-v2.spec.ts`, BUG-QA-35.
- [x] iPhone: «Уже куплено» → «Відмінити» → знову «Ви берете»; без «Відмінити» через кілька секунд — «Куплено», і після перезавантаження теж — пройдено 22 листопада
- [x] Куплена картка → «Не купили? Змінити в „Моїх бронях“» → «Ще не куплено» → картка знову «Ви берете» — пройдено 22 листопада

## Знайдене в застосунку на iPhone, 21 листопада

### BUG-QA-33 — форма позиції їде вбік; «Додати» недосяжна; вікно мерехтить

**Де:** iPhone, встановлений застосунок (PWA), форма нової позиції, «Вписати вручну», версія 0.2.17.
**Факт:** 1) з'являється горизонтальна прокрутка; 2) після введення ціни й «✓» на клавіатурі до «Додати» не можна дістатися; 3) один раз угорі почалося мерехтіння, ніби вікно закривається й відкривається, — минуло лише після повного закриття застосунку.
**Причина:** текст у полях — 15 px, а iPhone збільшує сторінку, щойно фокус потрапляє в поле з шрифтом менше 16 px, і назад сам не повертає. «Вписати вручну» ставить фокус у назву — звідси збільшення й прокрутка вбік. Далі `useKeepPage` (BUG-QA-31) вважав збільшення лише за висотою (< 80 %), а 7 % його не зачіпали: хук повертав сторінку при кожній прокрутці й боровся з iOS — кнопка ставала недосяжною, а вікно мерехтіло.
**Виправлено (0.2.18):** на сенсорному екрані текст у полях — від 16 px; `useKeepPage` не чіпає збільшену сторінку (`visualViewport.scale`). У Chrome на телефонних ширинах переповнення форми немає (320, 375, 390 px). E2E — `guest-v2.spec.ts`: поля від 16 px на профілі `mobile`.
- [x] iPhone, застосунок: «Додати позицію» → «Вписати вручну» → назва, ціна → «✓» на клавіатурі → «Додати» натискається; прокрутки вбік немає, сторінка не збільшується — пройдено 22 листопада
- [x] Те саме в Safari на iPhone — пройдено 22 листопада

### BUG-QA-34 — «Змін чекають на мережу» лишається після повернення мережі

**Де:** iPhone, встановлений застосунок, версія 0.2.17.
**Кроки:** режим польоту → зміна в списку (лягає в чергу) → вимкнути режим польоту, увімкнути Wi-Fi.
**Факт:** смуга «Змін чекають на мережу» не зникає.
**Причина:** черга відправлялась лише при відкритті застосунку й на подію `online`. На iPhone вона приходить, коли Wi-Fi уже ввімкнено, а запити ще падають, — або не приходить, якщо застосунок був у фоні, поки людина гортала Пункт керування. Невдала спроба не повторювалась. Окрім того, після режиму польоту `navigator.onLine` буває хибним, а запити до бази при `false` відхилялись одразу — навіть «Надіслати зараз».
**Виправлено (0.2.18):** відправка ще й при поверненні застосунку на екран; невдала спроба повторюється через 5, 15, 30 с і далі щохвилини; черга відправляється в мережу без огляду на `navigator.onLine`. E2E — `session.spec.ts`: перша відправка після повернення мережі падає, а черга відправляється сама.
- [x] iPhone, застосунок: режим польоту → змінити статус позиції → вимкнути режим польоту → смуга зникає сама за кілька секунд, без перезапуску — пройдено 22 листопада
- [x] Те саме, але режим польоту вимикати з Пункту керування, не виходячи із застосунку — пройдено 22 листопада

## Знайдене в Telegram на iPhone, 20 листопада

### BUG-QA-32 — аркуш «Беру» відкривається з клавіатурою, яка накриває «Забронювати»

**Де:** вбудований браузер Telegram на iPhone, гостьова сторінка `/l/…`, аркуш «Беру» (`BookSheetV2`), версія 0.2.16.
**Кроки:** відкрити посилання на список із чату → «Беру» на позиції.
**Очікувано:** аркуш із назвою подарунка й кнопкою «Забронювати» на виду; клавіатура — лише після дотику до поля.
**Факт:** курсор одразу в полі «Як вас підписати», клавіатура піднімається сама й накриває «Забронювати»; заголовок аркуша зсунуто вгору під адресний рядок Telegram.
**Причина:** рідний `showModal()` ставить фокус у перше поле вікна, а iOS на такий фокус показує клавіатуру. Те саме було в усіх аркушах із полем угорі; це пункт U-3 аудиту (ROADMAP 8.25), який на телефоні виявився помилкою, а не дрібницею.
**Виправлено (0.2.17):** на сенсорному екрані `SheetV2` переносить фокус із поля на саме вікно; на компʼютері поведінка та сама. E2E — `guest-v2.spec.ts`, профілі `chromium` і `mobile`.
- [x] Перевірити в Telegram на iPhone тими самими кроками: аркуш без клавіатури, «Забронювати» видно; торкнутись поля — клавіатура зʼявляється, «Забронювати» досяжна після «Готово» — пройдено 21 листопада
- [x] Те саме в Safari на iPhone і в Chrome на Android — пройдено 21 листопада
